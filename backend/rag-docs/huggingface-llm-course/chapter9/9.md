# End-of-chapter quiz


Let's test what you learned in this chapter!

### 1. What can you use Gradio to do?

**Choices**
- Create a demo for your machine learning model
  - Explanation: With a few lines of python code you can generate a demo for your ML model using our library of pre-built components.
- Share your machine learning model with others
  - Explanation: Using the <code>share=True</code> parameter in the launch method, you can generate a share link to send to anyone.
- Debug your model
  - Explanation: One advantage of a gradio demo is being able to test your model with real data which you can change and observe the model's predictions change in real time, helping you debug your model.
- Train your model
  - Explanation: Gradio is designed to be used for model inference, AFTER your model is trained.

### 2. Gradio ONLY works with PyTorch models

**Choices**
- True
  - Explanation: Gradio works with PyTorch models, but also works for any type of machine learning model!
- False
  - Explanation: Gradio is model agnostic, meaning you can create a demo for any type of machine learning model.

### 3. Where can you launch a Gradio demo from?

**Choices**
- Standard python IDEs
  - Explanation: Gradio works great with your favorite IDE.
- Google Colab notebooks
  - Explanation: You can create and launch a demo within your Google colab notebook.
- Jupyter notebooks
  - Explanation: Good choice - You can create and launch a demo within your Jupyter notebook.

### 4. Gradio is designed primarily for NLP models

**Choices**
- True
  - Explanation: Gradio works with pretty much any data type, not just NLP.
- False
  - Explanation: Gradio supplies developers with a library of pre-built components for pretty much all data types.

### 5. Which of the following features are supported by Gradio?

**Choices**
- Multiple inputs and outputs
  - Explanation: Multiple inputs and outputs is possible with gradio. All you need to do is pass in a list of inputs and outputs to their corresponding parameters
- State for data persistance
  - Explanation: Gradio is capable of adding state to your interface.
- Username and passwords authentication
  - Explanation: Pass in a list of username/password tuples to the launch method to add authentication.
- Automatic analytics for who uses your gradio demo
  - Explanation: Try again - Gradio does not supply developers analytics on who uses their demos.
- Loading a model from Hugging Face's model hub or Hugging Face Spaces
  - Explanation: Absolutely - load any Hugging Face model using the <code>gr.Interface.load()</code> method

### 6. Which of the following are valid ways of loading a Hugging Face model from Hub or Spaces?

**Choices**
- gr.Interface.load('huggingface/{user}/{model_name}')
  - Explanation: This is a valid method of loading a Hugging Face model from the Hub
- gr.Interface.load('model/{user}/{model_name}')
  - Explanation: This is a valid method of loading a Hugging Face model from the Hub
- gr.Interface.load('demos/{user}/{model_name}')
  - Explanation: Try again -- you cannot load a model by using the 'demos' prefix.
- gr.Interface.load('spaces/{user}/{model_name}')
  - Explanation: This is a valid method of loading a Hugging Face model from Spaces

### 7. Select all the steps necessary for adding state to your Gradio interface

**Choices**
- Pass in an extra parameter into your prediction function, which represents the state of the interface.
  - Explanation: An extra parameter storing history or state of your interface is necessary.
- At the end of the prediction function, return the updated value of the state as an extra return value.
  - Explanation: This history or state value needs to be returned by your function.
- Add the state input and state output components when creating your Interface
  - Explanation: Gradio provides a state input and output component to persist data.

### 8. Which of the following are components included in the Gradio library?

**Choices**
- Textbox.
  - Explanation: Yes, you can create textboxes with the Textbox component.
- Graph.
  - Explanation: There is currently no Graph component.
- Image.
  - Explanation: Yes, you can create an image upload widget with the Image component.
- Audio.
  - Explanation: Yes, you can create an audio upload widget with the Audio component.

### 9. What does Gradio `Blocks` allow you to do?

**Choices**
- Combine multiple demos into one web app
  - Explanation: You can use the `with gradio.Tabs():` to add tabs for multiple demos
- Assign event triggers such as clicked/changed/etc to `Blocks` components
  - Explanation: When you assign an event, you pass in three parameters: fn: the function that should be called, inputs: the (list) of input component(s), and outputs: the (list) of output components that should be called.
- Automatically determine which `Blocks` component should be interactive vs. static
  - Explanation: Based on the event triggers you define, `Blocks` automatically figures out whether a component should accept user input or not.
- Create multi-step demos; meaning allowing you to reuse the output of one component as the input to the next
  - Explanation: You can use a component for the input of one event trigger but the output of another.

- False
  - Explanation: Just like `Interface`, all of the sharing and hosting capabilities are the same for `Blocks` demos!
