  - Explanation: Right! There are no limits when uploading models to the Hub.

  - Explanation: No requirement is set regarding the field of application!

  - Explanation: Incorrect!
- Through git and git-lfs.

### 4. What is a model card?

**Choices**
- A rough description of the model, therefore less important than the model and tokenizer files.
  - Explanation: It is indeed a description of the model, but it's an important piece: if it's incomplete or absent the model's utility is drastically reduced.
- A way to ensure reproducibility, reusability, and fairness.
  - Explanation: Correct! Sharing the right information in the model card will help users leverage your model and be aware of its limits and biases. 
- A Python file that can be run to retrieve information about the model.
  - Explanation: Model cards are simple Markdown files.

### 5. Which of these objects of the 🤗 Transformers library can be directly shared on the Hub with `push_to_hub()`?

#### PyTorch
**Choices**
- A tokenizer
  - Explanation: Correct! All tokenizers have the <code>push_to_hub</code> method, and using it will push all the tokenizer files (vocabulary, architecture of the tokenizer, etc.) to a given repo. That's not the only right answer, though!
- A model configuration
  - Explanation: Right! All model configurations have the <code>push_to_hub</code> method, and using it will push them to a given repo. What else can you share?
- A model
  - Explanation: Correct! All models have the <code>push_to_hub</code> method, and using it will push them and their configuration files to a given repo. That's not all you can share, though.
- A Trainer
  - Explanation: That's right — the <code>Trainer</code> also implements the <code>push_to_hub</code> method, and using it will upload the model, its configuration, the tokenizer, and a model card draft to a given repo. Try another answer!
#### TensorFlow
**Choices**
- A tokenizer
  - Explanation: Correct! All tokenizers have the <code>push_to_hub</code> method, and using it will push all the tokenizer files (vocabulary, architecture of the tokenizer, etc.) to a given repo. That's not the only right answer, though!
- A model configuration
  - Explanation: Right! All model configurations have the <code>push_to_hub</code> method, and using it will push them to a given repo. What else can you share?
- A model
  - Explanation: Correct! All models have the <code>push_to_hub</code> method, and using it will push them and their configuration files to a given repo. That's not all you can share, though.
- All of the above with a dedicated callback
  - Explanation: That's right — the <code>PushToHubCallback</code> will regularly send all of those objects to a repo during training.
